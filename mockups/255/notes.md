# #255 · кабинет оператора — «Журнал»

Статичный макет (`index.html`, открывается двойным щелчком, без сборки). Пять кадров одного экрана.
Скриншоты: `D:\Agents\CRMDormitory-artifacts\mockups-255-1440.png` и `mockups-255-375.png`.

## Кадры

1. **Лента за период.** Раздел «Журнал» восьмым пунктом в навигации, перед «Реквизитами». Заголовок
   «Журнал», справа «Все компании платформы · время московское». Фильтры «От», «До», «Вид действий»,
   «Применить». Таблица из шести колонок «Когда / Компания / Сотрудник / Действие / Вид / Статус».
   Одна запись раскрыта: вторая строка той же таблицы с сырым JSON (высота 208px, скролл внутри).
   Подвал: «За этот период — 128 записей» слева, «Показать ещё» справа.
2. **Отказ по периоду (422).** «От» позже «До»: текст `detail` дословно в `role="alert"`, поля
   `aria-invalid`, кнопки «Повторить» нет — чинят вводом в фильтре. Так же выглядят «Период длиннее
   90 дней», «Период ещё не начался», «Такой даты нет в календаре».
3. **Пусто за период.** «За этот период записей нет» + даты выбранного периода в абзаце; фильтры
   остаются заполненными.
4. **Отказ шлюза (502).** «Основной API недоступен» и «Повторить» рядом (`.alert-line`, как в «Счетах»);
   ленты под отказом нет.
5. **Загрузка.** «Загружаем журнал…» в `role="status"` и скелет в той же таблице с теми же колонками;
   фильтры `disabled`, чтобы второй запрос не обгонял первый.

Состояние догрузки в кадр не попало, рисуется так: кнопка «Показать ещё» → `aria-busy="true"` и
подпись «Загружаем…», лента остаётся на месте; отказ догрузки — `.alert--error` под подвалом
(`operator-journal-more-error`), уже показанные строки не пропадают.

## Тексты и правила (дословно)

- Пусто: «За этот период записей нет». Загрузка: «Загружаем журнал…». 502: «Основной API недоступен».
- Подвал: «За этот период — N записей»; при `next_cursor = null` кнопки «Показать ещё» нет.
- Компания: `organization_id = null` → слово «Платформа» тёплым серым и без 600 — это не имя клиента.
  Неизвестная компания — приглушённым, как `.list__name--empty` в реестре организаций.
- Сотрудник: `actor_name`, иначе «Сотрудник №{id}», иначе «—» (тише, это не имя).
- Действие: `action_title`; если названия нет — код действия моно-набором
  (`.journal__action[data-unknown='true']`), выдуманных подписей не бывает.
- Вид: «Безопасность» / «Данные» / «Служебное» словами, без чипов; «Безопасность» — чернилами 600,
  «Служебное» приглушённое.
- Статус: точка + код + «мс». 2xx–3xx — шалфейная точка, остальные — кирпичная, `null` — полая и «—».
  Цвет не единственный носитель смысла: код ответа всегда рядом.
- Раскрытие: `summary` «Запись журнала» / «Скрыть запись», справа «№ 14821».

`data-testid`: `operator-nav-journal`, `operator-journal-from`, `operator-journal-to`,
`operator-journal-kind`, `operator-journal-apply`, `operator-journal-more`, `operator-journal-retry`;
для отказа догрузки — `operator-journal-more-error` (назван в постановке). Остальные — предложение,
менять можно.

## Брейкпоинты

- **≥ 1181:** как в кадрах, `.page--journal` 1280px, ячейки 12×16, лента на всю ширину.
- **761–1180:** таблица остаётся таблицей, ячейки 11×12, «Когда» и «Вид»/«Статус» уже, шрифт 12–12.5,
  доли колонок сдвинуты — иначе «Действие» выдавливает статус.
- **≤ 760:** шапка в две строки (навигация переносится, «Журнал» подчёркнут), фильтры в столбик,
  «Применить» на всю ширину, строка становится блоком: когда + статус, компания, действие, ниже
  сотрудник и вид; подвал `column-reverse` — сначала кнопка, потом счётчик. Скелет тоже три полосы.

## Что взято из продукта, что новое

Из `operator/frontend/src/index.css` без изменений: `.topbar`, `.nav`, `.page*`, `.field*`, `.btn*`,
`.alert`, `.alert--error`, `.alert-line`, `.list`, `.list__table`, `.list__foot`, `.list__shown`,
`.empty*`, `.state`, `.visually-hidden`, токены цвета и радиусов.

Новое (переносится в `index.css` вместе с разметкой): `.journal__table` и доли колонок,
`.journal__when/__date/__time`, `.journal__company(--platform)`, `.journal__actor(--none)`,
`.journal__action([data-unknown])`, `.journal__kind(--security/--noise)`,
`.journal__status([data-state])` с тремя тонами `.status-dot`, `.details-row`, `.summary`,
`.summary__chevron`, `.json-wrap`, `.json`, `.skeleton*`. Один новый токен — `--font-mono`
(системный стек), цветов не добавлено.

Новая анимация одна: пульс скелета; `prefers-reduced-motion` выключает его и спиннер кнопки.
Фокус — 2px шалфея с отступом 2px, как в продукте.

## Что в макет не входит

- Обработчики, запросы, состояние, параметры URL, разбор ответов — только вид.
- Раскрытие записи — нативный `<details>`, а не JS-панель; сортировки нет, клика по строке нет.
- Фильтра по компании и поиска в этом круге нет (постановка их не просит).
- Выгрузки CSV, автообновления, живого «новые записи сверху» нет.
- Клиентский журнал (`app/frontend`) и его состояния (свой период, курсор, запрет, «нет решения»)
  здесь не показываются — это другой экран.
- Продуктовый код, стили приложения, схемы и API не менялись.
