# Макет #126 — Кабинет оператора: вход и пустая страница

Статичный макет первого экрана отдельного приложения `operator/`. Открывается двойным щелчком,
без сборки, зависимостей и шрифтов по сети.

## Оформление — из референса `dis/1.jpg`

Стиль «natural neutral»: мягкий беж, лён, шалфей, тёплый серый, линии 1px, малые радиусы,
нейтральный гротеск вместо Nunito. Печатные hex в картинке не совпадают со свотчами
(`#FBD6C8` / `#37A999` / `#644872`), поэтому значения сняты с пикселей:

| Токен | Значение | Роль |
| --- | --- | --- |
| `--n-beige` (soft beige) | `#E2D9CA` | выделение, hover-подложка, selection |
| `--n-linen` (linen) | `#E8E1D7` | фон марки, вторичная подложка |
| `--n-sage` (sage green) | `#9CA590` | акцент, основная кнопка, фокус |
| `--n-sage-dark` | `#8C9581` | hover основной кнопки |
| `--n-grey` (warm grey) | `#79726A` | приглушённый текст, тонкие иконки |
| `--n-grey-deep` | `#3A362F` | обводки и текст второстепенной кнопки |
| `--n-ink` | `#262420` | заголовки и основной текст |
| `--n-page` (paper) | `#F0EEE8` | фон страницы приложения |
| `--n-canvas` | `#E7E5DE` | фон листа макета (не продукт) |
| `--color-border` / `-strong` | `#DEDBD3` / `#C9C4B9` | линии 1px |
| `--color-danger` (brick) | `#8A4B33` на `#F3E6DF` | ошибка — в референсе её нет, цвет выведен |

Геометрия: кнопки 44px, радиус 10px, шрифт 600 14.5px; поля 44px, радиус 10px, паддинг 11/14;
карточки радиус 14px, рамка 1px, тень почти незаметная (`0 1px 2px rgba(58,54,47,.04)`);
иконка в пустом блоке — тонкая линия 1.4 без плашки; шапка белая с линией 1px снизу.
Типографика: `'Segoe UI', system-ui, …`, заголовок карточки 600 22px, подписи полей 600 12.5px.

**Это расхождение с основным кабинетом осознанное**: у операторского приложения свои токены.
Продуктовые `:root` / `.btn` / `.field` сюда не копируются — при вёрстке эти значения идут в
`operator/frontend/src/index.css`. Структура экрана осталась продуктовой (шапка `.shell .topbar`,
карточка `.activate__card`, `.field`), чтобы экран читался как «Домовой».

Чего в референсе нет и что пришлось решить: цвет ошибки, фокус клавиатуры (2px шалфея, отступ
2px), состояния кнопок (hover — только цвет, без подъёма), пустой блок.

## Экраны

1. **`/login`** — шапка кабинета (марка «Домовой» слева, подпись «Кабинет оператора» справа) и
   карточка входа: заголовок «Вход в кабинет оператора», пояснение, поля «Логин» и «Пароль»,
   кнопка «Войти» на всю ширину карточки. Без «Забыли пароль?» и без регистрации — их нет в
   кабинете. Логин, а не email: экран не должен повторять вход основного кабинета.
2. **`/`** — шапка с брендом, логином `operator` и кнопкой «Выйти»; тело — белая карточка
   `.empty`: «Данных пока нет» и строка о том, что обмен с основным кабинетом ещё не подключён.
   Пустота объяснена словами — экран не читается как недоделанный.

## Состояния

| Состояние | Как выглядит |
| --- | --- |
| пусто | поля пустые, «Войти» активна, Enter отправляет, логин подсказан placeholder'ом `operator` |
| отправка | кнопка `disabled aria-busy="true"`, текст «Вход…», индикатор; поля и значения остаются |
| ошибка входа | `.alert--error` над кнопкой, `role="alert"`, текст — дословно `detail` сервера; оба поля `aria-invalid` (рамка кирпичом, подложка `#FDF9F7`); значения не стираются |
| клиентская проверка пустых полей | `.field__error` под полем: «Укажите логин» / «Укажите пароль», запрос не уходит. В кадре не нарисовано — то же поле с рамкой ошибки без общего алерта |
| сеть / 5xx | тот же алерт с текстом контракта: «Не удалось войти. Попробуйте ещё раз» |
| проверка сессии | на `/` только `<p role="status">Проверяем сессию…</p>`, без формы и без действия в шапке; `401` → `/login` |

## Брейкпоинты

- **1440** — карточка `min(100%, 25rem)` по центру под шапкой 68px, отступы контента 32/40/48.
- **760** — шапка 60px, отступы 20px, карточка на всю ширину, заголовок 19px, поля и кнопка не
  выходят за экран.
- **375** — ошибка переносится по словам, «Выйти» и логин помещаются в шапке, подпись «Кабинет
  оператора» скрывается (она есть в заголовке карточки).
- Сам лист макета в узком окне показывает только кадры 375: сжимать 1440-px вёрстку в 375 px —
  не проверка ширины 375.

## Тексты

- Заголовок карточки: «Вход в кабинет оператора»; пояснение: «Логин и пароль выдаёт
  администратор. Восстановления пароля здесь нет.»
- Подписи полей: «Логин», «Пароль». Кнопка: «Войти», на отправке — «Вход…».
- Ошибка сервера: дословно `detail`, контрактный текст — «Неверный логин или пароль»
  (один и тот же для неверного логина и пароля). Пустые поля: «Укажите логин», «Укажите пароль».
- Шапка: «Домовой», подпись «Кабинет оператора», логин `operator`, кнопка «Выйти».
- Пустая страница: «Данных пока нет» и «Обмен с основным кабинетом ещё не подключён — кабинет
  оператора пока умеет только вход. Разделы появятся, когда обмен включат.»
- Статус проверки сессии: «Проверяем сессию…».

## Что в макет не входит

- Обработчики, роутер, запросы, состояния в JS: это кадры, а не приложение.
- Меню, разделы, шапка с навигацией, данные: в задаче их нет — только шапка, форма и пустое тело.
- Правки `app/**`: продуктовый код, стили, схема и API не менялись; основной кабинет остаётся на
  кремовой бумаге, мяте и Nunito — новый стиль живёт только в `operator/`.
- Восстановление пароля, роли, второй оператор, «запомнить меня»: в контракте их нет.
- Обращения в основной API и CORS: кабинет в этой задаче не делает запросов в основной кабинет.
- Иконки из CDN, внешние шрифты, картинки: марка «Домовой» нарисована инлайновым SVG; фото и
  градиент из референса не переносятся.
- Ночная тема, плотная/просторная плотность, второй акцентный цвет.
