# Макет #126 — Кабинет оператора: вход и пустая страница

Статичный макет первого экрана отдельного приложения `operator/`. Токены, шрифты, кнопки и
поля взяты из `app/frontend/src/index.css` (`:root`, `.btn`, `.form`, `.field`, `.alert`),
шапка и пустой блок — из `src/workspace/Workspace.module.css` (`.shell .topbar`, `.brand`,
`.empty-state`). Продуктовый код не менялся; ничего нового визуального языка — это та же
«Домовой» на тех же значениях.

## Экраны

1. **`/login`** — шапка кабинета (бренд «Домовой» слева, подпись «Кабинет оператора» справа) и
   карточка входа: заголовок «Вход в кабинет оператора», пояснение, поля «Логин» и «Пароль»,
   кнопка «Войти» на всю ширину карточки. Без «Забыли пароль?» и без регистрации — их нет в
   кабинете. Логин, а не email: экран не должен повторять вход основного кабинета.
2. **`/`** — шапка с брендом, логином `operator` и кнопкой «Выйти»; тело — блок `.empty`:
   «Данных пока нет» и строка о том, что обмен с основным кабинетом ещё не подключён.
   Пустота объяснена словами — экран не читается как недоделанный.

## Состояния

| Состояние | Как выглядит |
| --- | --- |
| пусто | поля пустые, «Войти» активна, Enter отправляет, логин подсказан placeholder'ом `operator` |
| отправка | кнопка `disabled aria-busy="true"`, текст «Вход…», индикатор из `.btn[aria-busy]`; поля и введённые значения остаются |
| ошибка входа | `.alert--error` над кнопкой, `role="alert"`, текст — дословно `detail` сервера; оба поля `aria-invalid` (рамка `--color-danger`); значения не стираются |
| клиентская проверка пустых полей | `.field__error` под полем: «Укажите логин» / «Укажите пароль», запрос не уходит. В кадре не нарисовано — это то же поле с красной рамкой, без общего алерта |
| сеть / 5xx | тот же `.alert--error`, текст контракта: «Не удалось войти. Попробуйте ещё раз» |
| проверка сессии | на `/` только `<p role="status">Проверяем сессию…</p>`, без формы и без действия в шапке; `401` → `/login` |

## Брейкпоинты

- **1440** — карточка `min(100%, 26rem)` по центру под шапкой 76px, отступы контента 36/40/48.
- **1100 и 760** — точки кабинета из `DESIGN.md`; на 760 шапка 68px, отступы 20px, карточка на
  всю ширину, заголовок карточки 21px, поля и кнопка не выходят за экран.
- **375** — карточка и поля на всю ширину, ошибка переносится по словам, «Выйти» и логин
  помещаются в шапке, подпись «Кабинет оператора» скрывается (она есть в заголовке карточки).
- Сам лист макета (`index.html`) в узком окне показывает только кадры 375: сжимать 1440-px
  вёрстку в 375 px — не проверка ширины 375.

## Тексты

- Заголовок карточки: «Вход в кабинет оператора»; пояснение: «Логин и пароль выдаёт
  администратор. Восстановления пароля здесь нет.»
- Подписи полей: «Логин», «Пароль». Кнопка: «Войти», на отправке — «Вход…».
- Ошибка сервера: дословно `detail`, контрактный текст — «Неверный логин или пароль»
  (один и тот же для неверного логина и пароля). Пустые поля: «Укажите логин», «Укажите пароль».
- Шапка: «Домовой», подпись «Кабинет оператора», логин `operator`, кнопка «Выйти».
- Пустая страница: «Данных пока нет» и «Обмен с основным кабинетом ещё не подключён — кабинет
  оператора пока умеет только вход. Разделы появятся, когда обмен включат.»
- Статус проверки сессии: «Проверяем сессию…».

## Что в макет не входит

- Обработчики, роутер, запросы, состояния в JS: это кадры, а не приложение.
- Меню, разделы, шапка с навигацией, данные: в задаче их нет — только шапка, форма и пустое тело.
- Восстановление пароля, роли, второй оператор, «запомнить меня»: в контракте их нет.
- Обращения в основной API и CORS: кабинет в этой задаче не делает запросов в основной кабинет.
- Иконки из CDN, внешние шрифты, картинки и логотип как файл: марка «Домовой» нарисована тем же
  инлайновым SVG, что в `Cabinet.tsx`. Nunito / Nunito Sans по сети не грузятся.
- Правила фокуса и контраста менять не нужно: `:focus-visible` продукта (1px `--color-focus`,
  отступ 3px) и токены AA взяты как есть.
