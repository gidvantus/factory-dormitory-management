# Макет #109 — конструктор уведомлений по общежитиям

Статичный прототип: `mockups/109/index.html` (открывается двойным щелчком, без сборки).
Токены, каркас и компоненты скопированы из `app/frontend/src/index.css` и
`app/frontend/src/workspace/Workspace.module.css` — новых цветов, радиусов и шрифтов нет.
Продуктовый код, стили приложения, схема и API этим макетом не меняются.

## Экраны

1. **Раздел «Уведомления», блок «Правила уведомлений»** (`telegram-rules`) под карточкой
   подключения Telegram: селектор общежития (`telegram-rule-dormitory`), кнопка
   `telegram-rule-add`, строки правил (`telegram-rule-row-<id>`): название, условия одной
   строкой, таблица, поля сообщения, чекбокс включения (`telegram-rule-toggle-<id>`),
   «Удалить» (`telegram-rule-delete-<id>`).
2. **Диалог правила** (`telegram-rule-dialog`): название (`telegram-rule-name`) → таблица
   (`telegram-rule-table`) → условия до 4 (`telegram-rule-condition-<i>-column|operator|value`,
   `telegram-rule-condition-add`) → поля сообщения до 6 (`telegram-rule-field-<code>`) →
   «Проверить» (`telegram-rule-preview-button`, превью `telegram-rule-preview-text`) →
   «Сохранить правило» (`telegram-rule-save`). Превью стоит справа от формы и не уезжает
   вниз: правка условия и её результат видны одновременно.
3. **Тот же диалог с ошибкой**: блок `telegram-rule-error` с текстом из `detail` дословно
   (`Столбец недоступен. Измените правило`), условие с удалённым столбцом подсвечено
   `aria-invalid="true"`, превью пустое.
4. **Состояния блока** (галерея без остального экрана): загрузка (`telegram-rules-loading`),
   пусто (`telegram-rule-empty`), ошибка загрузки (`telegram-rules-error`, кнопка
   «Повторить»), «Решение не подключено» (ответ 403).

Сломанное правило (`broken: true`) — строка 3 первого экрана: пометка
`telegram-rule-broken-<id>` «Столбец удалён, правило не работает», правило остаётся
в списке, удаление доступно всегда.

## Решения, которые нужно повторить

- **Условие — фраза, а не набор полей**: столбец, оператор и значение стоят одной строкой в
  общем лотке; вид значения зависит от типа столбца (дата → `input type="date"`, число →
  текстовое поле, список → `select` с опциями, чекбокс → `Да`/`Нет`). Для `not_empty` и
  `is_empty` контроля значения нет.
- **Лимиты показаны как ёмкость**, а не как ошибка: «2 из 4» у условий, «3 из 6» у полей.
- **Порядок строк сообщения** задают номера перед отмеченными полями; номера — только у
  отмеченных, у остальных место сохранено пустым.
- **Политика**: недоступные поля не скрыты, а выключены с подписью «только для
  пользовательских вкладок»; подпись под списком объясняет, почему полей мало.
- **Превью — ровно сообщение**: имя правила, пустая строка, строки `Поле: значение`.
  Строка «Под правило подходят N строк» приходит из ответа превью, не считается на клиенте.
- На ≤760 строка правила перестраивается в карточку, у таблицы и сообщения появляются
  подписи «Таблица» / «Сообщение»; на ≤600 условия становятся тремя полями в столбик,
  а кнопки диалога — на всю ширину (основная сверху).

## Брейкпоинты

Кабинет: **1100** (сайдбар 220px, отступы 28px), **760** (сайдбар скрыт, кнопка меню,
отступы 20px), **600** (формы в один столбец, условия и кнопки в столбик), **900**
(диалог из двух колонок становится одним столбцом, превью уходит вниз под форму).

## Тексты (дословно)

- Название блока: «Правила уведомлений», подпись: «Срабатывают, когда вы сохраняете строку в
  таблице общежития. Приходят только вам.»
- Пусто: «Правил пока нет» + «Создайте правило: выберите таблицу, задайте условия по
  столбцам — и сообщение придёт в Telegram, когда строка под них подойдёт.»
- Загрузка: «Загружаем правила…»; ошибка: «Не удалось загрузить правила. Проверьте
  соединение.» + «Повторить».
- Сломанное правило: «Столбец удалён, правило не работает».
- 403: «Решение не подключено» + «Уведомления в Telegram — отдельное решение: подключите его
  в магазине улучшений.» + «В магазин улучшений» (тексты существующей страницы, не новые).
- Отказы 422/404 — из `detail` без переписывания; в макете показан один: «Столбец недоступен.
  Измените правило».
- Операторы: равно, не равно, больше, меньше, заполнено, не заполнено.

## Чего в макете нет

- Счётчик/накопление, тихие часы, отправка по расписанию и воркер по датам — следующая
  поставка.
- Порядок полей перетаскиванием: показан номерами; механика изменения порядка — решение
  реализации, в макете её нет.
- Подтверждение удаления правила: удаление показано кнопкой без диалога.
- Мобильное меню в открытом виде, страницы 403 целиком и экран «нет права» отдельно: 403
  показан только как состояние блока.
- Тексты полей вне политики (телефон, суммы, документы, даты) — их в сообщении быть не может.

## Что стоит знать фронтендеру

- «Отключить» в карточке подключения Telegram — существующая кнопка `.btn` без рамки и
  заливки; макет её не перерисовывает, это не новая кнопка.
- На 375 кнопки этой карточки не помещаются в строку (подпись «Прислать тестовое
  уведомление» вылезала за карточку). В макете добавлено правило: на ≤600 кнопки идут в
  столбик, основная — на всю ширину. Правка существующей карточки, в объём #109 не входит —
  вынести отдельной задачей или согласовать с постановщиком.
- Список правил — не `<table>`, а грид-строки (`.rule-row`) с шапкой на 10px uppercase:
  на 375 они перестраиваются по `grid-template-areas` без второй вёрстки.
- Nunito и Nunito Sans в макете не подключены по сети: если гарнитуры нет на машине, стек
  падает на Segoe UI. В продукте шрифты приходят из `index.html` как раньше.
- Иконки — существующие из `WorkspaceIcon` (`people`, `lock`, `info`); своего колокольчика
  в наборе нет, поэтому пустое состояние использует `people`. Если для блока появится своя
  иконка, размер тот же: 22px внутри плитки 48×48.
- Все `data-testid` из контракта расставлены в разметке макета — можно сверять построчно.
