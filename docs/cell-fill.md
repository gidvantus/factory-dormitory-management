# Заполнение ячеек из других таблиц

В пользовательской подвкладке откройте «Настроить» и нужный столбец. Настройка
также доступна при создании таблицы и в отдельном редакторе столбца.

Пример «Отпуск»:

1. Создайте текстовый столбец «ФИО», выберите способ «Выбор записи», таблицу
   «Проживающие» и её столбец с ФИО.
2. У столбца типа «Дата» выберите «Из другой таблицы», ту же таблицу,
   нужный столбец даты и столбец выбора записи «ФИО».
3. Для дат начала и окончания отпуска оставьте «Вручную».

Источниками служат таблицы текущего общежития, включая пользовательские, и
реестр сотрудников организации. В реестре доступны ФИО, табельный номер и
телефон. Даты берутся из конкретной таблицы общежития: у сотрудника может быть
несколько исходных записей с разными датами. Другая организация и таблицы
другого общежития недоступны. Поиск выбора различает одинаковые имена по
табельному номеру и ID записи; сами связи сохраняют ID, а не имя.

«Обновлять автоматически» читает актуальное значение при открытии таблицы,
возвращении в окно и каждые 30 секунд, пока страница видна. При ошибке обновления
появляется сообщение и кнопка повтора. Обновление не заменяет ручные черновики.
Отчёты и дашборд вычисляют значение из источника при своём запросе.

«Скопировать один раз» фиксирует значение при выборе записи или изменении
правила. Изменение и удаление исходной записи копию не меняют. Смена выбранной
записи создаёт новую копию, очистка выбора убирает её. Пустые значения остаются
пустыми; ноль и «Нет» сохраняются. Связанные ячейки доступны только для чтения.

Настройка поддерживает текст, число, дату и чекбокс. Значения списков и мест
проживания доступны как текстовые подписи. Источник и получатель должны быть
совместимы по типу. Служебные действия не используются. Выбор записи доступен
для текстового столбца. Назначенный полю персонала столбец нельзя одновременно
сделать связанным: сначала измените существующее назначение.

При возврате к ручному вводу появляются прежние ручные значения. Удаление
используемого источника, столбца выбора или поля блокируется до изменения
связей. Скрытие не удаляет источник. Исчезновение исходной записи показывается
ошибкой в ячейке; в режиме копирования сохранённое значение остаётся доступным.
При фильтрации по связанной дате строки без доступной даты не попадают в период.
Циклические и чрезмерно длинные связи отклоняются сервером.

Шаблоны всей структуры и отчёта переносят правила с новыми ID столбцов без
выбранных записей и значений. Шаблон отчёта включает структуры источников
связанных ячеек. При выборе части шаблона структуры нужно включить таблицы,
на которые ссылаются ячейки. Копирование отдельной вкладки между общежитиями
может использовать существующий совместимый стандартный столбец получателя;
если его или пользовательского источника нет, требуется шаблон полной структуры.

## Хранение и API

Миграция `0051_cell_fill`, следующая за `0050_arrival_workflow`, добавляет:

- `table_columns.fill` — правило либо `null` для ручного ввода;
- `custom_tab_entries.fill_selections` — выбранные ID с таблицей-источником;
- `custom_tab_entries.fill_copies` — разовые снимки с подписью правила.

`custom_values` не перезаписывается производными значениями. Ответы строк
дополняются `fill_values`, `fill_errors` и `fill_selections`. Снимки не выдаются
отдельно и маскируются в журнале действий. Обычная запись ячейки со связью
отклоняется сервером.

`ColumnRequest` принимает необязательное `fill`: `mode` (`pick` / `lookup`),
`source` (ключ таблицы либо `personnel`), `field` (ID столбца строкой либо поле
персонала), `match_column_id` и `update` (`live` / `copy`). Старые запросы без
`fill` продолжают работать; при редактировании они сохраняют прежнее правило.
Явное `null` отключает связь. При пакетном создании столбцов `client_id` —
отрицательный временный ID; ссылки на него разрешаются в одной транзакции.

В пределах `/api/dormitories/{dormitory_id}/cell-fill`:

- `GET /sources` — таблицы и доступные поля;
- `GET /records?source=…&field=…&search=…` — поиск, до 50 результатов по умолчанию;
- `PUT /{table_key}/rows/{row_id}/selection/{column_id}` с `record_id` либо `null`;
- `GET /{table_key}/values` — актуальные связанные ячейки таблицы.

Все маршруты проверяют `OwnDormitory` до чтения данных. Правила на сервере
проверяются и при прямом изменении столбца, и при пакетном сохранении структуры.
Миграция применяется штатным запуском API при отдельном обновлении стенда.

Проверки: `tests/test_cell_fill.py` и
`src/workspace/dormitories/CellFill.test.tsx`; прежний независимый макет остаётся
на `/preview/cell-fill`.
