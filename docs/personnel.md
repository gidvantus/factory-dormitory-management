# Персонал

Рабочий раздел: `/cabinet/personnel`. Демонстрационный макет `/preview/personnel` остаётся отдельным и не меняет рабочие данные.

## Карточки и таблицы

`employees.id` — постоянный UUID человека. Строки «Проживающих», «Притока», «Оттока», архива и пользовательских таблиц хранят `employee_id`. ФИО, табельный номер и телефон остаются в исходных строках: сведения из разных общежитий могут отличаться.

Создание записи из интерфейса сначала вызывает `/api/personnel/check`. Пользователь выбирает существующую карточку, нового человека или временную карточку для проверки. Перед записью сервер повторяет проверку под общим транзакционным замком PostgreSQL. Изменившийся результат требует повторного выбора. Совпадение фамилии или табельного номера не объединяет людей автоматически; отсутствие общих данных не позволяет гарантированно найти дубль.

Старые маршруты добавления пустой строки сохранены для совместимости. При первом заполнении такой строки создаётся временная карточка; возможные совпадения доступны в разделе «Совпадения».

Для пользовательских таблиц и архива поля сопоставляются с ID столбцов через «Связь с персоналом». Переименование столбца сохраняет связь. Сопоставление не объединяет людей автоматически.

## История и объединение

События `employee_events` сохраняют снимки исходных данных, общежитие, дату и автора. Обновление строки, перевод, отток и удаление записываются в той же транзакции, что и исходная операция. Перевод и оформление оттока сохраняют ID человека. История удалённой строки остаётся доступной; сведения, удалённые до внедрения раздела, восстановить нельзя.

Объединение создаёт отменяемую связь между карточками через `merged_into_id`. Исходные строки, события, задачи, заметки и планы не перезаписываются: сводка собирает всю группу. При отмене исходные данные снова разделяются; добавленные после объединения записи остаются у выбранной основной карточки. Проверенное решение «разные сотрудники» скрывает пару до изменения идентификационных данных.

Сводка считает карточки, а не строки. Пока остаются временные карточки или несколько записей текущего проживания у одного человека, интерфейс сообщает о необходимости проверки.

## Работа

Продление меняет `Resident.shift_end`. Согласованный выезд создаёт план, но не завершает проживание; фактический отток оформляется из исходной таблицы. После оформления оттока план выезда закрывается. План следующего заезда проверяется на пересечение с текущей вахтой; при оформлении проживания в соответствующем общежитии наступивший план закрывается.

Задачи, заметки и планы общие для пользователей с действующим доступом к проекту, как и существующие таблицы общежитий. Блоки, сохранённые списки и избранные сотрудники сохраняются отдельно для пользователя. Ревизия настроек защищает от перезаписи изменениями из другого окна.

## Миграция и проверки

`0023_personnel` создаёт таблицы раздела и ссылки из исходных таблиц. Каждая непустая существующая стандартная строка получает отдельную карточку со статусом `pending` и начальное событие. Автоматического объединения нет. Перед применением нужна резервная копия базы. Откат миграции удаляет данные нового раздела, поэтому после начала работы для восстановления нужна резервная копия.

Проверки: `tests/test_personnel.py`, общие тесты переводов и оттока, `src/workspace/personnel/personnel.test.tsx` и тесты добавления строк трёх стандартных таблиц.
