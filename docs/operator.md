# Кабинет оператора

Отдельное приложение рядом с основным кабинетом: вход по логину и паролю из
конфига, список организаций платформы и карточка организации с правкой
реквизитов. Своей базы и своих данных у кабинета нет: организации кабинет
**не хранит** — читает и правит он их в основном API по внутренней сети и
сервисному токену (`X-Operator-Token`), поэтому источник правды, правила и
журнал остаются в основном приложении.

Создания и удаления организаций в кабинете нет, миграций в задаче не было.

## Что где лежит

```
operator/
├── backend/            — FastAPI: вход, проверка сессии, выход, health
│   ├── app/            — config.py, security.py, schemas.py, main.py, api/
│   ├── tests/          — pytest
│   └── Dockerfile
└── frontend/           — React + TypeScript + vite: вход, список и карточка
    ├── src/            — api/, auth/, components/, lib/, pages/, test/
    ├── nginx.conf      — статика SPA и прокси /api/ в operator-api
    └── Dockerfile
```

Список, карточку и правку организаций кабинет-API не хранит: он проксирует их в
основной API по внутренней сети с сервисным токеном (`api/organizations.py`).

Оба сервиса объявлены в корневом `docker-compose.yml` — `operator-api` и
`operator-web`, без профиля: стенд поднимается одной командой, как раньше.

## Как поднять

```bash
docker compose up -d --build
```

Правка `.env` не нужна: умолчаний из `.env.example` достаточно, если порты
свободны.

Адреса по умолчанию:

- кабинет оператора — http://localhost:8081 (`operator-web`);
- API кабинета — http://localhost:8002 (`operator-api`);
- health обоих: `GET /healthz` у фронтенда и `GET /api/health` у API.

Если стендов на машине несколько, запускайте свой под отдельным именем
(`docker compose -p <имя> ...`): имя проекта и порты у каждого стенда свои.
Имя проекта Docker принимает только строчными буквами.

## Переменные `.env`

| Переменная | Значение по умолчанию | Что значит |
| --- | --- | --- |
| `OPERATOR_USERNAME` | `operator` | логин единственного оператора; не секрет |
| `OPERATOR_PASSWORD` | нет (в примере `change-me`) | пароль оператора; без него сервис не стартует |
| `OPERATOR_TOKEN_SECRET` | нет (в примере заглушка) | секрет подписи сессии кабинета, не короче 16 символов; **не** `JWT_SECRET` основного приложения |
| `OPERATOR_TOKEN_TTL_HOURS` | `12` | срок жизни сессии в часах; он же уходит в `Max-Age` cookie |
| `OPERATOR_SESSION_COOKIE_SECURE` | `false` | отдавать cookie только по https |
| `OPERATOR_API_PORT` | `8002` | порт API кабинета на хосте |
| `OPERATOR_FRONTEND_PORT` | `8081` | порт фронтенда кабинета на хосте |
| `OPERATOR_SERVICE_TOKEN` | нет (в примере заглушка) | сервисный токен контура «кабинет → основной API»; его читают **оба** сервиса (`api` и `operator-api`), потому что имя переменной у них одно. Пустое значение закрывает платформенные ручки основного API (`401`), а кабинет отвечает `503`. Это **не** `TELEGRAM_SERVICE_TOKEN` и не `OPERATOR_TOKEN_SECRET`: у каждого свои права |

Реальные значения `OPERATOR_PASSWORD`, `OPERATOR_TOKEN_SECRET` и
`OPERATOR_SERVICE_TOKEN` в репозитории не
хранятся: `.env.example` держит имена и заглушки, свои значения кладутся в `.env`.
На боевом стенде порты публикуются на `127.0.0.1` (см. `docs/ssl.md`).

## Контракт API

Всё под префиксом `/api` того же origin: nginx кабинета проксирует `/api/` в
`operator-api:8000`, поэтому cookie остаётся first-party. Схема — `/openapi.json`
и `/docs` на `operator-api`.

| Метод | Путь | Ответ |
| --- | --- | --- |
| `POST` | `/api/auth/login` | `200 {"username": "operator"}` и `Set-Cookie: operator_session=…; HttpOnly; SameSite=lax; Path=/; Max-Age=43200`; неверная пара — `401 {"detail": "Неверный логин или пароль"}` (один текст на неверный логин и неверный пароль) |
| `GET` | `/api/auth/me` | `200 {"username": "operator"}` или `401 {"detail": "Требуется авторизация"}` |
| `POST` | `/api/auth/logout` | `204` без тела, cookie гасится теми же атрибутами; без сессии — тоже `204` |
| `GET` | `/api/health` | `200 {"status": "ok"}` |
| `GET` | `/api/organizations?limit=50&offset=0` | `200 {"items": [{"id", "name", "inn", "created_at"}], "total": N}`, свежие сверху; `limit` 1..100, `offset` ≥ 0 |
| `GET` | `/api/organizations/{id}` | `200 {"id", "name", "inn", "kpp", "ogrn", "address", "created_at", "members_count", "dormitories_count"}`; архивные общежития в счётчике считаются, владелец в участниках тоже |
| `PATCH` | `/api/organizations/{id}` | `200` — тот же объект, что у карточки. Тело: `name`, `inn`, `kpp`, `ogrn`, `address`; кабинет-фронт отправляет все пять, `null` в реквизите очищает поле |

Сессия — httpOnly cookie `operator_session`, в JS токена нет.

Все ручки организаций — под сессией кабинета (без cookie `401 {"detail":
"Требуется авторизация"}`) и проксируют запрос в основной API
(`/api/platform/organizations`) с заголовком `X-Operator-Token`. Отказы данных
передаются **тем же кодом и тем же `detail`**, что и в основном API:

| Код | `detail` | Когда |
| --- | --- | --- |
| `404` | `Организация не найдена` | неизвестный `id` |
| `409` | `Организация с таким ИНН уже есть` | ИНН занят другой организацией |
| `422` | `Название не может быть пустым`, `ИНН должен состоять из 10 или 12 цифр` | правка с пустым названием или ИНН не по формату |
| `502` | `Основной API не принял сервисный токен` | основной API ответил `401` |
| `502` | `Основной API недоступен` | сеть, таймаут или `5xx` основного API |
| `503` | `Кабинет не настроен: не задан OPERATOR_SERVICE_TOKEN` | пустой секрет; в сеть запрос не уходит |

Текстом отказа владеет основной API: кабинет-API его не переписывает, а
фронтенд показывает дословно. `502` — не истёкшая сессия: кабинет при этом не
разлогинивает.

## Фронтенд

Маршруты:

- `/login` — форма входа: логин и пароль, ничего больше (восстановления пароля и
  регистрации у кабинета нет);
- `/` — список организаций под `RequireOperator`: при монтировании
  `GET /api/auth/me`, пока ждём — «Проверяем сессию…», `401` — редирект на
  `/login`. Шапка с логином и «Выйти» живёт на обоих экранах кабинета;
- `/organizations/:id` — карточка организации под той же проверкой сессии;
- остальные адреса редиректят на `/`.

Форма входа: пусто; отправка (кнопка неактивна, «Вход…»); клиентская проверка
пустых полей («Укажите логин», «Укажите пароль», запрос не уходит); отказ сервера —
текст `detail` дословно в `role="alert"`; сеть/`5xx` — «Не удалось войти.
Попробуйте ещё раз».

Список организаций:

- загрузка — «Загружаем организации…» в `role="status"`, счётчик не показывается;
- ошибка — текст `detail` дословно в `role="alert"` (в том числе «Основной API
  недоступен» и «Кабинет не настроен: не задан OPERATOR_SERVICE_TOKEN»);
- пусто — «Организаций пока нет»;
- заполненный реестр: `№`, «Название», «ИНН», «Создана», «Открыть»; счётчик в
  заголовке равен `total`; название `null` показывается как «Без названия»;
- «Показать ещё» догружает следующую страницу (`limit`/`offset`) и исчезает,
  когда показано столько же, сколько `total`.

Карточка организации: просмотр (реквизиты и счётчики участников и общежитий),
правка на месте (все пять полей), «Сохранить» отправляет все пять полей,
«Отмена» возвращает значения последнего ответа сервера. `404` — «Организация не
найдена» и ссылка «К списку». Отказ сохранения (`409`, `422`) показывается
дословно, введённые значения не сбрасываются, фокус возвращается в форму. На
отправке «Сохранить» неактивна и говорит «Сохраняем…».

Поиска и фильтров по списку нет: только постраничная выдача. Создания и удаления
организаций нет.

Для тестировщика `data-testid`:

| Экран | `data-testid` |
| --- | --- |
| вход | `operator-login-username`, `operator-login-password`, `operator-login-submit`, `operator-login-error` |
| шапка кабинета | `operator-logout` |
| список | `operator-organizations`, `operator-organizations-empty`, `operator-organizations-error`, `operator-organizations-more`, `operator-organization-row` (на каждой строке), `operator-organization-open` |
| карточка | `operator-organization-card`, `operator-organization-name`, `operator-organization-inn`, `operator-organization-kpp`, `operator-organization-ogrn`, `operator-organization-address`, `operator-organization-edit`, `operator-organization-save`, `operator-organization-cancel`, `operator-organization-error`, `operator-organization-back` (ссылка «К списку») |

В режиме правки те же `operator-organization-name/-inn/-kpp/-ogrn/-address`
носят поля формы: выписка на это время заменяется формой, и один
`data-testid` всегда указывает на одно и то же поле организации — значение в
просмотре, поле ввода в правке. `operator-organization-error` — отказ и
загрузки, и сохранения: одновременно их не бывает.

Dev-режим без контейнеров:

```bash
cd operator/frontend
npm ci
npm run dev
```

Vite проксирует `/api` на `http://localhost:8002` (порт `operator-api` по
умолчанию); другой адрес задаётся переменной `VITE_API_PROXY_TARGET`, а не правкой
конфига.

Оформление — «natural neutral» из макетов (`mockups/126/` — вход, `mockups/131/` —
список и карточка): свои токены в `operator/frontend/src/index.css`, продуктовые
стили `app/frontend` не переиспользуются. Шрифты — системный стек, по сети
ничего не грузится.

## Проверки

Бэкенд:

```bash
docker compose exec operator-api python -m pytest
docker compose exec operator-api ruff check .
docker compose exec operator-api mypy .
```

Фронтенд — из `operator/frontend`:

```bash
npm ci
npm run build      # tsc --noEmit && vite build
npm run lint       # eslint .
npx prettier --check .
npm run test       # vitest run
```

## Чего здесь нет

- Создания организаций, удаления и архива: в API нет `DELETE`-семантики, а
  организация без владельца невидима никому.
- Поиска и фильтров по списку сверх постраничной выдачи; поиска по ИНН в DaData
  (все пять полей правятся руками); участников организации, приглашений, тарифов
  и подписок.
- CORS и обмена с фронтендом основного кабинета (`app/frontend`): браузер
  кабинета ходит только в свой `operator-api` через nginx того же origin.
- Своей базы, alembic и миграций.
- Ролей, второго оператора, восстановления пароля, «запомнить меня», меню и
  других разделов кабинета.
- Видимости действий оператора в журнале основного кабинета: у строк
  платформенного контура нет организации, раздел «Журнал» читает по ней.
- TLS, домена и маршрута в caddy: профиль `tls` кабинет не затрагивает.
