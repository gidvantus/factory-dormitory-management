# CRM Dormitory

Проект для учёта рабочих на общежитиях.

## Назначение

CRM-система ведёт учёт рабочих, проживающих в общежитиях: заселение и выселение,
распределение по комнатам и местам, кадровые и бытовые данные. Система нужна
комендантам и кадровой службе, чтобы видеть актуальную занятость мест и историю
проживания.

## Возможности

- реестр рабочих: карточка, подразделение, статус;
- реестр общежитий: здания, комнаты, места;
- заселение, переселение и выселение с историей;
- отчётность по занятости мест.

В разделе «Общежития» уже доступны создание (название общежития и клиента),
карточки с клиентом перед названием и переход внутрь общежития. Данные сохраняются
в PostgreSQL. Пока все вошедшие пользователи видят общий список; разграничение
доступа будет добавлено вместе с ролями и правами. Создатель записывается для учёта
авторства.

Название общежития и клиента можно изменить кнопкой «Редактировать» на карточке.
«В архив» меняет статус без удаления данных: карточка становится
тусклой с пометкой «Архив», данные продолжают участвовать во всех расчётах дашборда.
«Восстановить» возвращает активный статус. Доступ к таблицам архивного общежития сохраняется.
Архивные карточки отображаются после активных; кнопки управления находятся только на карточках.

В таблицах «Проживающие», «Приток», «Отток», «На аванс», «На расчёт» и «Архив»
доступны кнопки «Добавить столбец» и «Настроить столбцы». Для нового столбца
выбирается текст, число, дата, чекбокс или выпадающий список с вариантами.
Настройки сохраняются отдельно для каждого общежития и таблицы. Столбцы можно
переименовать, удалить из таблицы и восстановить вместе с данными. Тип после
создания неизменяемый; использованные варианты списка можно архивировать.

В «Проживающих» кнопки «Записать» на аванс и расчёт копируют значения в соответствующий
список выплат в том же общежитии. Сравниваются текущие названия и типы всех действующих
столбцов, включая добавленные пользователем; регистр и лишние пробелы не учитываются.
Удалённые столбцы и служебные кнопки пропускаются. Варианты выпадающих списков
сопоставляются по названию. Поля без пары остаются пустыми; о несовместимых значениях
показывается сообщение. Кнопка дожидается сохранения ячеек строки. Проживающий остаётся
в исходном списке, а данные выплаты сохраняются отдельно и не меняются вслед за ним.
Повторная запись того же проживающего в тот же список не создаёт дубликат и не затирает
выплату; также проверяется совпадение табельного номера с существующими выплатами.
После удаления выплаты или очистки списка можно записать проживающего снова.
Кнопка «Перевести» в «Проживающих» открывает выбор другого активного общежития.
До переноса сравниваются текущие столбцы двух таблиц: названия, типы и выбранные
варианты списков. Совпадающие данные переносятся с новыми идентификаторами
пользовательских столбцов и вариантов; хостел сопоставляется по названию среди
действующих в текущем месяце. Если поле отсутствует, удалено или несовместимо,
показывается причина и требуется подтверждение перевода без этого поля.
Заполненные скрытые столбцы также перечисляются перед потерей данных.
При изменении строки или столбцов после сравнения требуется повторная проверка.
Перевод атомарно перемещает одну строку, сохраняя её идентификатор; аванс и расчёт
остаются в исходном общежитии. Если в получателе уже есть такой Т/н, перевод блокируется.

Кнопка «Отток» сравнивает текущие столбцы «Проживающих» и «Оттока» этого общежития
по названию и типу, включая пользовательские столбцы. Окно содержит только подтверждение
переноса и удаления исходных записей, без списка полей и отдельного подтверждения потерь.
Совпадающие данные переносятся автоматически; дата выезда копируется только из
совпадающего столбца и иначе остаётся пустой. При удалении записей на аванс и расчёт
учитываются связанные с проживающим записи и ручные строки с тем же Т/н, за все даты
в этом общежитии. Записи, связанные с другим проживающим, не удаляются.
Создание оттока, удаление проживающего и его выплат выполняются одной транзакцией.
Если после сравнения менялись данные, столбцы или выплаты, требуется новое сравнение.
Миграция `0013_resident_payments` добавляет связь для проверки повторной записи;
существующие выплаты сохраняются. Удаление проживающего сохраняет данные его выплат.

В «На аванс» и «На расчёт» кнопка «Очистить список» удаляет все строки выбранной
подвкладки в текущем общежитии после подтверждения, включая записи вне выбранного
периода. Столбцы и другие списки сохраняются. При ошибке список остаётся на экране,
очистку можно повторить.

В «Большом отчёте» доступны ручные, формульные и связанные строки. Для связи
выбираются раздел, подвкладка, столбец и условие: «Равно выбранному значению»
или «Заполнено — любое значение». Каждая подходящая запись даёт 1. При выборе
столбца с датой по умолчанию считаются все заполненные даты с распределением
по этому же столбцу. Для остальных столбцов количество распределяется по дате создания записи в часовом
поясе Europe/Moscow; можно выбрать столбец с датой события. Записи с пустой датой
события пропускаются. Пустой результат даёт 0, нарушенная связь — ошибку.
Расчёт выполняется при загрузке отчёта, поэтому изменения и удаления источника
учитываются при следующем открытии или обновлении отчёта. Связанные строки можно
использовать в формулах; их ячейки не редактируются вручную. Удаление столбца,
на который ссылается отчёт, блокируется с указанием зависимых строк.

Шаблон отчёта переносит формулы, связи и структуру таблиц-источников в новое
общежитие с новыми идентификаторами столбцов, без записей и значений ячеек.
«Архив» содержит отдельные записи с настраиваемыми столбцами; автоматического
переноса проживающих в него пока нет.

Во вкладке «Места» свободные места рассчитываются автоматически за каждый день
и хостел: оплачено мест минус проживает, отдельно для М и Ж. Итог свободных мест
складывает оба результата. При изменении или очистке исходных ячеек расчёт
обновляется после автосохранения. Пустое исходное значение считается нулём;
если обе исходные ячейки пусты, результат остаётся пустым. Отрицательная разница
отображается без округления до нуля. Ручное редактирование свободных мест закрыто;
ранее сохранённые ручные значения сохраняются в базе и заменяются расчётом при выводе.

Миграция `0011_table_columns_links` добавляет настройки и дополнительные поля,
сохраняя существующие записи. При запуске API миграции применяются автоматически.

## Стек

- **Backend** — FastAPI (Python).
- **Frontend** — React + TypeScript.
- **База данных** — PostgreSQL, запуск через Docker Compose.

## Структура

```
.
├── app/
│   ├── backend/          — FastAPI: app/, alembic/, tests/, Dockerfile
│   └── frontend/         — React + TypeScript: src/, Dockerfile, nginx.conf
├── docker-compose.yml    — стенд: db + api + web
├── .env.example          — значения стенда по умолчанию (.env переопределяет)
└── README.md
```

## Запуск стенда

```bash
docker compose up -d --build
```

Адреса по умолчанию:

- Frontend — http://localhost:8080
- API — http://localhost:8001

Если на машине несколько стендов проекта, запускайте свой под отдельным именем,
чтобы не задеть контейнеры и том базы соседнего стенда:

```bash
docker compose -p <имя-стенда> up -d --build
```

## Процесс работы

- Базовая ветка — `main`, напрямую в неё не коммитят.
- Задача берётся из issue с меткой `ready-for-dev`; ветка задачи —
  `feature/<номер>-<краткий-слаг>`, например `feature/1-readme`.
- Итог оформляется pull request в `main`; мерж делает человек.
- После открытия pull request issue получает метку `ready-for-test`.
- Разработчик отвечает за статический анализ и юнит-тесты; E2E-проверки
  (Playwright), визуальные эталоны и отчёты о доступности — за тестировщиком.
