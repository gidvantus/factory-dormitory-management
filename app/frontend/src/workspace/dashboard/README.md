# Подключение данных дашборда

`Dashboard` использует `GET /api/dashboard?from=…&to=…` за включительный период не длиннее года. Сервер получает список действующих общежитий и рассчитывает значения обязательных формульных строк «Выход Итого», «Проживает Итого», «Текучка Итого» тем же способом, что и общий отчёт. Поэтому вновь созданные общежития автоматически входят в сводку.

Архивные общежития исключаются из всех данных обзора: сводки, клиентов, дневной
динамики, готовности отчётов, пользовательских блоков и каталога их источников.
Выбор архивного общежития для отдельного графика отвечает `404`; при обновлении
списка интерфейс сбрасывает исчезнувший выбор на общую динамику. Настройки
сохранённых блоков и данные общежитий сохраняются: после восстановления они
снова участвуют в расчётах. Архивирование не меняет вкладку «Общежития» и доступ
к её таблицам. При отсутствии действующих общежитий сводка показывает отсутствие
данных, списки пусты.

`loadDashboard(range, signal)` передаёт период и сигнал отмены в API. Карточки проживающих, выхода и текучки показывают срез на конец периода; в текущем месяце дата среза ограничена сегодняшним днём по часовому поясу Москвы. Будущие дни в график не попадают.

Выбор общежития в блоке «Динамика показателей» передаёт необязательный `dormitory_id`. Он ограничивает только дневные серии графика; общие карточки, разбивка и список клиентов всегда охватывают все общежития.

- `dormitories`: список действующих общежитий с постоянными ID. `residents`, `attendance`, `turnover` — срез на дату `snapshotDate`; `vacancies` пока не подключены.
- `clients`: выход на работу, сгруппированный по названию клиента; если клиенту принадлежат несколько общежитий, их значения суммируются.
- `totals`: общий выход и количество проживающих на ту же дату. Не суммировать дневную численность проживающих и выход за весь месяц.
- `turnover`: значение обязательной строки «Текучка Итого» на дату среза в карточке и за каждый день на графике.
- `daily`: одна запись на календарный день, показатели по всем общежитиям. Начальная формула обязательных строк `=0` тоже даёт ноль до настройки. `null` означает отсутствующую строку или ошибку формулы. График фильтрует диапазон включительно и не соединяет точки через пропуски.
- Не выдавать частичную сумму за общую, если по части общежитий нет данных. В таком случае передавать `null` до появления отдельного признака полноты.
- Календарь — `Europe/Moscow`, единый для текущего месяца и текущего дня (`dates.ts`).

## Оформление «Пульт руководителя»

Рабочий обзор использует выбранный вариант 3: тёмную бирюзовую сводку,
мини-графики выхода и текучки, цветные полосы сравнения и прогресс готовности
отчётов. Nunito и палитра сохраняют стиль кабинета; на телефоне сводка складывается
в одну колонку. Иллюстрации людей декоративные и не изображают реальных сотрудников.

Верхняя сводка и её мини-графики всегда относятся ко всем общежитиям.
Основной запрос загружает общие данные; при выборе общежития выполняется отдельный
запрос только для основного графика. При возвращении ко всем общежитиям используются
уже загруженные общие серии. Оба запроса отменяются при смене периода;
ошибка отдельного графика не очищает общую сводку.

Общая текучка складывается из срезов общежитий только при полной доступности
значений; иначе показывается «—». Ноль остаётся нулём. Мини-графики строятся
из дневных данных до даты среза: null и пропущенные даты разрывают линии.

«Отчёты сегодня» использует `report_readiness` на `reportDate`, независимо от
выбранного периода. Зелёный означает готовность, песочный — отчёт ещё не готов;
отсутствующий или устаревший статус отображается нейтрально и не считается
отказом. Время и автор готовности остаются в подсказке списка. Прогресс не зависит
от того, скрыт ли настраиваемый блок отчётов. Порядок, скрытие и пользовательские
блоки продолжают сохраняться прежним API.

Рабочий обзор не подставляет демонстрационные значения. Примерочная пяти
вариантов по адресу `/preview/overview` остаётся отдельной страницей.
