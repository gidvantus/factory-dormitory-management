# Конструктор подвкладок «Персонала»

Тестовый маршрут: `/preview/personnel-tab-builder`.
Этот маршрут остаётся изолированной тестовой копией. Рабочая версия подключена
в `/cabinet/personnel` через `PersonnelWithBuilder`: серверное хранение,
расчёт, версии и источники организации. Подробности — `docs/personnel-builder.md`.

## Текущий вариант — на штатной странице проекта

Маршрут открывает `PersonnelProjectPreview`: исходный `Personnel`, исходный
`ArrivalPlanningPage`, рабочие блоки, список, карточку и план заездов. Через
необязательное расширение добавлены только кнопки конструктора, дополнительные
вкладки и их содержимое. Без расширения кабинет сохраняет прежнее поведение.
Штатная страница не скопирована в отдельную версию разметки.

Вместо набора демонстрационных групп рядом с тремя основными разделами есть
одна вкладка «Учёт работы»: сотрудник, часы, ручная ставка, начислено по формуле
и телефон по связи с карточкой. Кнопки «Изменить формулу начисления» и
«Настроить связь с карточкой» открывают только нужное правило, позволяют выбрать
запись для проверки и применяют изменение сразу ко всей таблице. Полный
конструктор столбцов, форматов, вложенных таблиц и действий остаётся доступен.

Данные — отдельная локальная копия демонстрационных данных проекта. Штатные
API-объекты временно направляются в изолированные обработчики и восстанавливаются
при уходе со страницы. Работают настройки блоков, карточки и заметки, настройки
плана, добавление/редактирование/удаление, отметки и перенос заездов. Неподключённые
серверные операции (например, XLSX-экспорт выбранных сотрудников) явно сообщают
о недоступности в стенде; запрос в рабочий сервер не выполняется.

Для текущего варианта используются ключи `domovoy-personnel-project-builder-v1`
и `domovoy-personnel-project-data-v1`. Старый самостоятельный пример и его
хранилище сохранены. `PersonnelProjectPreview.test.tsx` проверяет штатные разделы,
живое редактирование и формулы, изменение связанного телефона через карточку,
создание вкладки, хранение, отсутствие сетевых вызовов и восстановление API.
`projectApi.test.ts` проверяет локальные периоды, ревизии, настройки и переносы.

## Возможности конструктора

Рядом с тремя основными подвкладками находятся свои подвкладки и кнопка
«Добавить подвкладку». Конструктор открывается штатным отдельным окном.

Предложены три типа:

- **Список сотрудников** — действующие фильтры реестра, общежития, условия по
  стандартным и пользовательским столбцам, выбор показываемых сведений.
  Используются штатные `filterPeople`, `EmployeeListFilters` и
  `PersonnelEmployeeFocus`. Сотрудники не копируются в отдельный реестр.
- **Своя таблица** — отдельные записи, порядок и обязательность столбцов,
  текст, число, дата, список, чекбокс и ссылка на сотрудника из реестра.
  Записи добавляются и редактируются отдельным окном. Заполненный столбец
  сохраняет тип, скрытые столбцы восстанавливаются с прежними значениями.
  Для таблиц используется штатный `CustomTabOptionsEditor` из общежитий:
  обычный список / дни в столбцах, без периода / диапазон / месяц,
  дата фильтрации, добавление, очистка всего списка, действия строк и
  показ дат. В формате по дням доступны текстовые отметки и числа, итоги
  по строкам и дням складывают только числовые значения видимого периода.
  Смена формата и месяца сохраняет обычные и дневные значения.
- **Рабочие блоки** — штатные `PersonnelWorkspaceBlock` и `BlockDialog`,
  отдельный набор блоков для каждой своей подвкладки, добавление и порядок.

Можно настроить поиск, CSV-выгрузку, фильтры на странице и действия с записями,
выбрать вкладку для открытия по умолчанию. В управлении доступны порядок,
скрытие, архив и восстановление. Три основные вкладки защищены от удаления.

В новой таблице можно выбрать образец из таблиц персонала или демонстрационных
вкладок общежитий. Копируются возможности и структура с новыми ID без записей.
Кнопка «Скопировать структуру» на готовой таблице работает так же.
При создании доступны группы с вложенными таблицами: у каждой свои записи
и настройки; скрытие и архив родителя скрывают всю группу без потери данных.
Существующие дочерние таблицы настраиваются отдельно; структура родителя служит
образцом для следующих вложенных таблиц.

В столбце и календарной строке выбирается источник значения: ручной ввод,
формула или связь. Формула поддерживает несколько действий `+ - * /`, скобки,
числовые константы и ссылки на другие столбцы этой записи / строки того же дня.
Используется безопасный арифметический парсер проекта без `eval`. Ссылки хранят
постоянные ID: переименование и перестановка не ломают расчёт.

Связь получает одно значение, количество, сумму, среднее, минимум или максимум.
Доступны сопоставление столбцов текущей записи и источника, несколько условий
отбора, ограничение по дате и поведение при отсутствии данных. Источники:
реестр сотрудников (включая пользовательские поля), свои таблицы персонала,
таблицы общежитий, строки общего отчёта, размещение и план заездов.
В календарях выбирается строка источника, расчёт выполняется за день ячейки;
в обычных таблицах учитывается выбранный период. Для календаря, отчёта и
размещения без периода используется доступный календарь / демонстрационная
дата. Сотрудники с несколькими значениями не сводятся к первому совпадению.
Неоднозначный поиск, текст вместо числа, деление на ноль, отсутствующие
зависимости и циклы показываются как ошибки. Ошибка зависимости передаётся
дальше по формуле. Расчётные ячейки доступны только для чтения.

Настройка столбцов остаётся в окне подвкладки; у календаря есть отдельное
окно «Правило и итоги» и кнопка добавления расчётной строки. Можно проверить
результат до сохранения, выбрать строки для общего итога. В CSV попадают
вычисленные значения, включая явные ошибки. Используемые столбцы, строки и
вкладки-источники защищены от скрытия / удаления / архива с объяснением
зависимости. Скрытие целой вкладки оставляет её доступной как источник.
При копировании структуры переносятся формулы и связи с переназначением ID;
календарные строки с правилами копируются без ручных и дневных значений.

Добавлена группа «Примеры расчётов»: «Ставки» → «Расчёт оплаты» и календарь
«План и факт» с формулой отклонения и связью с заездами. Можно редактировать
ставки, часы, доплату и дневной факт и сразу видеть пересчёт. Изменения заездов
на этой тестовой странице также обновляют источник до перезагрузки. Данные
общежитий, отчёта и размещения — локальные демонстрационные источники.

Исходные примеры: «Заканчивается вахта», «Учёт документов», «Учёт смен» и
«Примеры расчётов».
Свои вкладки, настройки, таблицы и блоки хранятся в `localStorage` под ключом
`domovoy-personnel-tab-builder-v1`. Версия данных 3 автоматически дополняет версии
1 / 2 настройками и новыми примерами единожды, сохраняя прежние записи и кнопки.
Заезды в основной вкладке демонстрируют
штатные окна на локальных данных; их черновики действуют до перезагрузки.
Карточки сотрудников в этом примере показывают сведения без изменения реестра.
API не вызывается; новый конструктор не включается в обычном кабинете.

Интерактивные проверки: `PersonnelTabBuilder.test.tsx` — создание и настройка,
сохранение после повторного открытия страницы, условия отбора, таблицы и
записи, архив, восстановление полей, ссылки на сотрудников и рабочие блоки.
`AdvancedTable.test.tsx` проверяет обновление прежних данных, периоды и их границы,
дневные значения между месяцами и форматами, кнопки, очистку и восстановление,
копирование из общежития и независимые вложенные таблицы.
`calculations.test.ts` проверяет арифметику, фильтры, источники и периоды,
цепочки, циклы и ошибки, стабильность ссылок, копирование правил и миграцию.
`CalculationsUI.test.tsx` проверяет настройку формул и связей через окна,
живой пересчёт, защиту зависимостей, ручное редактирование и CSV.
