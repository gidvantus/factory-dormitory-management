# Конструктор личных уведомлений

Тестовая страница `/preview/notification-builder`, без входа и запросов к API.
Демонстрационные таблицы представляют разные разделы компании; рабочие данные
и существующие уведомления не меняются. Сохранение — только в localStorage.

## Замысел

Сохраняем оформление «Домового»: белый `#ffffff`, кремовый `#fffdf9`,
чернильный `#27313d`, зелёный `#2f7d62`, мятный `#dceee4`, голубой `#dce9f7`.
Заголовки — Nunito, текст — Nunito Sans из действующих токенов.
Выравнивание влево, компактные формы, без декоративных иллюстраций.

Композиция: `[мои уведомления] [шаг конструктора] [живое сообщение Telegram]`.
На небольшом экране личный список сворачивается, предпросмотр идёт после формы.
Четыре последовательных шага: данные, условия, расписание, сообщение.
Главный акцент — сообщение с реальными для макета значениями и отдельными
блоками разных таблиц: пользователь сразу видит результат настройки.
Проверка замысла: вместо ещё одной таблицы правил показываем сборку сообщения,
при этом сохраняем привычные цвета, кнопки и плотность существующего кабинета.

## Принятые решения

- Настройки личные, в одном сообщении несколько самостоятельных блоков таблиц.
- Каждый блок выбирает таблицу, область данных, поля, период и условия.
- Предусмотрены отправка при событии, ежедневно, еженедельно, ежемесячно,
  через интервал и один раз; время, часовой пояс, дни недели.
- Если отправка в выходные отключена, суббота и воскресенье переносятся
  на понедельник и выводятся отдельно от понедельничных данных с подписями.
- Переключатель «Понедельник» показывает этот случай на демонстрационных данных.
- Сохранённый макет остаётся в браузере. Действия макета не отправляют Telegram.

## Размеры при внедрении

- Выбор источника: явная ширина до 860 px, ограниченная доступным экраном.
  Одного `max-width` недостаточно: базовый `.modal__panel` задаёт `width: 30rem`
  и оставляет окно узким. Локальный размер должен переопределять именно `width`.
- Карточки каталога перестраиваются автоматически; минимальная ширина 200 px,
  на более узком экране карточка занимает всю доступную ширину.
- Предпросмотр тестового сообщения соответствует колонке сообщения с учётом
  отступов диалога, вместо общего ограничения окна.
- При доступной ширине рабочей области до 900 px предпросмотр переносится под
  редактор. Измеряется сама рабочая область: левое меню реального кабинета
  также занимает место. На широком экране сохраняются две колонки.
- При внедрении проверить общие размеры полей, кнопок, отступов и окон по
  `src/DESIGN.md`, а также широкое окно, ноутбук, планшет и телефон; длинные
  названия таблиц и полей, прокрутку и доступность нижних действий.

Рабочий серверный каталог любых таблиц компании, права на источники, хранение
персональных настроек и выполнение расписания относятся к следующему этапу
после согласования этого интерфейса.
