# Домовой — лендинг, версия 1

Статичный прототип лендинга CRM для учёта рабочих, проживающих в общежитиях.
Светлая палитра (белый и кремовый фон), мультяшные иллюстрации с пастельными
заливками и тёмно-синим контуром.

## Как посмотреть

Открыть в браузере файл:

```
landing/index.html
```

Всё работает без сборки и без сервера: CSS и SVG подключаются относительными
путями. Шрифты Nunito и Nunito Sans подтягиваются с Google Fonts; без интернета
страница остаётся читаемой на системном шрифте.

## Запуск в Docker

Образ — `nginx:1.27-alpine` со статикой и своим конфигом `nginx.conf`
(gzip, кэш для CSS и SVG, `healthz` для проверки живости).

```bash
cd landing
docker compose up -d --build
```

Страница: http://localhost:8080

Без compose:

```bash
cd landing
docker build -t domovoy-landing:local .
docker run -d --name domovoy-landing -p 8080:80 domovoy-landing:local
```

Остановить: `docker compose down` (или `docker rm -f domovoy-landing`).

## Что на странице

1. **Шапка** — липкая, с меню и двумя действиями («Войти», «Запросить демо»).
2. **Герой** — заголовок, описание, две кнопки, три показателя и иллюстрация
   с двумя плашками поверх («занятость 92%», «46 свободных мест»).
3. **Кому подходит** — три роли с аватарами и списком задач каждой роли.
4. **Возможности** — шесть блоков: реестр проживающих, заселение и выселение,
   общежития и места, отчёты, кадровые данные, роли и доступы.
5. **Как это работает** — четыре шага внедрения.
6. **Интерфейс** — макет рабочего места коменданта: боковое меню, плитки
   занятости, таблица проживающих со статусами.
7. **Отчётность** — диаграмма заполняемости по пяти общежитиям.
8. **Отзывы** — два отзыва с аватарами.
9. **Вопросы** — пять раскрывающихся блоков.
10. **Демо** — форма с рабочей почтой и иллюстрации (дом, кот, пёс).
11. **Подвал** — логотип, разделы, копирайт.

## Что это прототип, а не рабочий продукт

- **Цифры вымышленные**: 4 800 мест, 12 общежитий, 92% занятости, список
  проживающих и адреса. Перед публикацией заменить на реальные или убрать.
- **Форма не отправляет данные**: обработчик только показывает сообщение,
  запроса на сервер нет.
- **Ссылки «Войти» и «Запросить демо»** ведут на якорь `#demo`, а не в систему.
- **Отзывы** — придуманные; для публикации нужны настоящие с согласием людей.
- **Название «Домовой»** рабочее. Если есть утверждённое имя, заменить в шапке,
  подвале, `<title>`, мета-описании и в подписи логотипа.

## Куда смотреть при правках

| Что меняем | Где |
|---|---|
| Цвета, тени, радиусы, шкала шрифтов | `styles.css`, блок `:root` |
| Тексты | `index.html`, соответствующий раздел |
| Цифры и таблицу в макете | `index.html`, раздел `#interface` |
| Диаграмму заполняемости | `index.html`, раздел `#reports` (ширины в `style="width:…"`) |
| Иллюстрации | `assets/*.svg`, правила — в `ILLUSTRATION-STYLE.md` |

Цвета и размеры берутся только из переменных `:root`. Если нужного токена нет,
добавляем семантический токен, а не подставляем hex в компонент.

## Перенос в React + TypeScript

Разметка разделов переносится почти без изменений: каждый раздел — отдельный
компонент, `styles.css` подключается как глобальный или разбирается на
CSS-модули по компонентам.

1. `hero` → `Hero.tsx`, `roles` → `RolesSection.tsx`, `features` →
   `FeaturesSection.tsx`, `how` → `StepsSection.tsx`, `interface` →
   `InterfaceSection.tsx`, `reports` → `ReportsSection.tsx`, `reviews` →
   `ReviewsSection.tsx`, `faq` → `FaqSection.tsx`, `demo` → `DemoSection.tsx`.
2. Карточки ролей и возможностей вынести в данные-массивы и рендерить
   циклом: сейчас они свёрстаны явно, чтобы страница открывалась без JS.
3. Иконки — инлайновые SVG. Для React их стоит вынести в компоненты
   (`Icon.tsx`) либо заменить на библиотеку с теми же 24×24 контурами.
4. Иллюстрации оставить файлами в `assets/` и импортировать как ссылки,
   либо превратить в React-компоненты, если понадобится менять цвета из темы.
5. Интерактив в конце `index.html` (тень шапки, появление секций, форма)
   переносится в `useEffect` / обработчик формы.
6. Шрифты: подключить локально (`.woff2`) вместо Google Fonts, чтобы лендинг
   работал во внутренней сети без доступа наружу.

## Доступность

- Контраст текста проверен: основной текст 12,98:1, вторичный 6,51:1,
  ссылки и акценты 4,89:1 и выше (норма WCAG AA — 4,5:1).
- Есть ссылка «К основному содержанию», видимый фокус (`:focus-visible`),
  `lang="ru"`, семантические заголовки, `aria-label` у диаграммы и меню макета.
- Иллюстрации декоративные: у них пустой `alt`, смысл несут тексты рядом.
- Анимация появления уважает `prefers-reduced-motion`.
- Таблица макета прокручивается по горизонтали на узких экранах, а не обрезается.
